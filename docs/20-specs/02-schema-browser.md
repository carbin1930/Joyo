# spec-02：库表浏览（Schema Browser）

- 规格编号：spec-02
- 功能名称：库表浏览
- 所属版本：v0.1
- 状态：已定稿并实现（v0.1，已打 tag v0.1.0）
- 依赖 spec：spec-01

## 1. 功能描述

连接成功后，以树形结构浏览该实例的数据库 → 表 → 列，并可查看表结构详情（列定义、索引、建表 DDL）（关联 PRD US-03）。

## 2. 界面设计

连接列表下方（同一侧栏）为**对象树**区域：

```
▼ joyo-dev（连接名，绿点=已连接）
  ▼ mysql            ← 数据库（schema）节点
    ▼ user           ← 表节点
        id bigint PK
        name varchar(64)
    ▶ order_item
  ▶ information_schema
```

- 节点按需懒加载：库节点在连接成功后加载；表节点在库节点展开时加载；列节点在表节点展开时加载
- 每级右上角有刷新按钮（刷新当前层级）
- 树顶部有过滤输入框：按名称前缀/包含匹配过滤当前已加载节点（纯前端过滤）
- 单击表节点 → 右侧主区域切换为**表详情**（三个 Tab：列 / 索引 / DDL）

## 3. 接口依赖

见 `rest-api.md` 元数据节：列出数据库、列出表、表详情（列/索引/DDL）。

## 4. 行为细节

1. **数据库列表**：通过 `information_schema.SCHEMATA` 查询，按名称排序；系统库（`information_schema`、`mysql`、`performance_schema`、`sys`）正常展示但排在前缀分组之后
2. **表列表**：`information_schema.TABLES` WHERE TABLE_SCHEMA=?，含表类型（BASE TABLE / VIEW），视图节点用不同图标
3. **表详情-列**：名称、类型（含长度，如 `varchar(64)`）、可空、键（PRI/UNI/MUL）、默认值、注释
4. **表详情-索引**：索引名、类型、包含列（按 SEQ_IN_INDEX 排序）、唯一性
5. **表详情-DDL**：`SHOW CREATE TABLE`，只读代码块展示，带复制按钮
6. **双击表名查看表数据**（2026-11-06 修订，原"双击插入表名"改为快捷键）：双击对象树里的表 → 新建 SQL 页签并立即执行 `SELECT * FROM `库`.`表` LIMIT 1000`（默认前 1000 条，与行数限制默认值一致）；查询走带库名的全限定名，避免页签默认库不同查错表。**Ctrl/⌘ + 双击**保留旧行为：把表名插入活动 SQL 页签编辑器光标处（同库 `` `表名` ``、跨库 `` `库名`.`表名` ``，反引号转义；无页签时提示先创建）
7. **列清单嵌在表节点下方**（2026-11-06 修复）：展开某表时，列清单紧跟在**该表行之下**缩进展示（此前是独立循环渲染，列总出现在所有表名之后），列顺序按 `ORDINAL_POSITION`
8. 连接断开（显式或后端报告连接失效）时，整棵树清空并显示"未连接"

## 5. 边界情况

| 场景 | 期望表现 |
|---|---|
| 元数据查询失败（权限不足等） | 节点显示"加载失败"，可点击重试，toast 显示错误 |
| 表数量很大（>1000） | 表节点分页/虚拟滚动，不一次性渲染全部 DOM |
| 表名/库名含特殊字符（反引号、空格、中文） | 后端拼接元数据 SQL 时统一用参数绑定或合法转义 |
| 连接中途失效（MySQL gone away） | 树清空，侧栏绿点熄灭，提示"连接已断开，请重新连接" |
| 用户无某库的 SELECT 权限 | 该库可展开但表列表报权限错误，节点显示"无权限" |

## 6. 验收标准

- [ ] 连接后可见全部数据库，展开任意库可见全部表（含视图标识）
- [ ] 展开表可见列清单；表详情三个 Tab 数据与真实结构一致
- [ ] DDL 与 `SHOW CREATE TABLE` 原文一致且可复制
- [ ] 过滤框输入 `user` 时仅保留名称含 user 的节点
- [ ] 断开连接后树被清空；重连后可重新加载
- [ ] 对含特殊字符的表名（如 `` `order item` ``）能正确加载详情

## 7. 扩展点（只设计不实现）

- 树节点结构预留 `type` 字段（table / view / partitioned），v1.0 可加触发器、存储过程节点
