# 功能规格模板

> 新建 spec 时复制本模板，编号递增。所有小节为必填（不适用的写"无"）。

## 0. 元信息

- 规格编号：spec-NN
- 功能名称：
- 所属版本：v0.x
- 状态：草稿 / 已定稿 / 已实现
- 依赖 spec：spec-MM（无则写"无"）

## 1. 功能描述

用 3-5 句话说明本功能是什么、解决什么用户问题（关联 PRD 用户故事编号）。

## 2. 界面设计

描述界面布局、组件、交互流（放线框图或文字描述）。明确：入口在哪、主要状态有哪些（空态 / 加载 / 错误 / 正常）。

## 3. 接口依赖

列出本功能用到的后端接口（引用 `docs/30-api/rest-api.md` 中的端点；新接口先在该文档登记再开发）。

## 4. 行为细节

核心逻辑的精确描述：输入、处理规则、输出。规则要具体到可以直接写测试用例。

## 5. 边界情况

逐条列出异常输入、失败场景及期望表现。

## 6. 验收标准

可测试的 CheckList，每条以"给定…当…则…"或直接可验证的陈述书写。**全部通过才算 spec 完成。**

## 7. 扩展点（只设计不实现）

为后续版本预留的接口形状或代码位置，防止返工。
