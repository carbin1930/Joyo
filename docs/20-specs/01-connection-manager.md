# spec-01：连接管理

- 规格编号：spec-01
- 功能名称：连接管理
- 所属版本：v0.1
- 状态：已定稿
- 依赖 spec：无

## 1. 功能描述

用户可以新建、编辑、删除、测试 MySQL 连接配置。连接信息持久化在本地，密码经系统钥匙串机制加密（关联 PRD US-01、US-02）。这是整个应用的入口功能。

## 2. 界面设计

主界面左侧为**连接列表侧栏**（宽 260px）：

- 顶部："+ 新建连接"按钮
- 列表项：连接名称 + 主机摘要（`host:port`），单击选中，双击发起连接
- 右键菜单：编辑 / 删除 / 复制连接

**连接编辑对话框**（新建与编辑共用）字段：

| 字段 | 控件 | 必填 | 默认值 | 校验 |
|---|---|---|---|---|
| 名称 | 文本框 | 是 | `host-port` | 非空，≤ 50 字符 |
| 主机 | 文本框 | 是 | 127.0.0.1 | 非空，合法主机名或 IP |
| 端口 | 数字框 | 是 | 3306 | 1-65535 |
| 用户名 | 文本框 | 是 | root | 非空 |
| 密码 | 密码框（可显隐） | 否 | 空 | 无 |
| 默认数据库 | 文本框 | 否 | 空 | 无 |

对话框底部按钮：`测试连接`（异步，结果显示在按钮旁）、`保存`、`取消`。编辑时密码框留空表示不修改。

状态约定：保存中按钮 loading；测试中禁止重复点击；删除需二次确认弹窗（显示连接名）。

## 3. 接口依赖

见 `docs/30-api/rest-api.md` 连接管理节：连接增删改查、测试连接、建立/断开会话。

注意分工：**connections.json 的读写与加解密全部在 Electron Main 进程**；后端只接收解密后的连接参数做真正的数据库操作，不持久化任何连接信息（见 `data-model.md`）。

## 4. 行为细节

1. **新建**：填表 → 保存 → Main 生成 UUID、加密密码、原子写文件 → 列表刷新
2. **测试连接**：`POST /connections/test`，直接携带表单当前值（含未保存的修改）；成功显示"连接成功（耗时 xxx ms，MySQL x.x.x）"，失败显示错误码对应文案
3. **双击连接**：调用建立会话接口 → 成功后该连接项显示绿点，触发 schema 树加载（spec-02）；失败弹 toast 并保持未连接态
4. **删除**：仅删除本地配置，若处于已连接状态需先断开会话再删
5. 应用启动时不自动连接任何数据库，仅展示列表

## 5. 边界情况

| 场景 | 期望表现 |
|---|---|
| 主机不可达 | 测试/连接返回 2001，提示"无法连接到主机，请检查地址与网络" |
| 认证失败 | 2002，提示"用户名或密码错误" |
| 连接超时（默认 5s） | 2003，提示"连接超时" |
| 密码密文解密失败（如换机器后钥匙串不匹配） | 该连接标记"密码失效"，连接时提示重新输入密码 |
| connections.json 损坏 | 按 `data-model.md` 第 3 节处理，UI 提示配置已重置 |
| 重名连接 | 允许保存但列表项副标题显示 host:port 区分 |
| 删除已连接的连接 | 先断开会话成功后再删除本地配置 |

## 6. 验收标准

- [ ] 新建连接保存后重启应用，列表仍在；双击可连接
- [ ] 打开 connections.json，密码字段以 `enc:v1:` 开头，无明文
- [ ] 编辑连接不修改密码，原密码仍有效
- [ ] 测试连接对错误密码返回明确失败文案
- [ ] 删除连接有二次确认；删除后文件中该条目消失
- [ ] 应用退出后重新打开，无残留的"已连接"绿点状态
