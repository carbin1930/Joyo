- 规格编号：spec-16
- 功能名称：表数据编辑（F08）
- 所属版本：v0.4
- 状态：已定稿并实现（2026-10-26。实现说明：可编辑性在查询时由后端判定（`ResultSetMetaData.getTableName` 判单表 + `information_schema.COLUMNS` 取主键，要求主键列全部出现在结果列中，结果被 maxRows 截断时不可编辑）；`/mutations` 一个请求一个事务，语句后端参数化生成（标识符 `SqlIdentifiers.quote` + 列名按 information_schema 白名单校验）；UPDATE/DELETE 影响 0 行视为失败并整体回滚；前端改动按"全局行号"索引（新增行用负数行号），翻页不丢，保存成功后重跑当前 SQL 刷新）
- 依赖 spec：spec-01（连接模型）、spec-03（查询执行，结果附带可编辑信息）、spec-04（结果网格，复用其 Tabulator 网格与 NULL/BLOB 展示约定）

## 1. 功能描述

结果网格从只读升级为**可编辑**（PRD F08、范围 2026-10-22 确认：增删改全做）。用户执行一条单表 SELECT 后，可解锁编辑、在网格内直接改单元格 / 新增行 / 删除行；改动先留本地并打脏标记，点"保存"先弹确认框展示变更摘要，确认后由后端**在一个事务里**按主键执行 INSERT / UPDATE / DELETE，成功后重跑 SQL 刷新结果。

设计动机：日常改数常是"查出来 → 改两个字段 → 保存"，切到外部客户端或手写 UPDATE 语句成本高；但网格误触改库的代价极高，因此**默认锁定**，改动需显式解锁 + 确认，且后端按主键精确定位，杜绝"漏 WHERE 全表更新"。

## 2. 界面设计

**编辑工具栏**（`ResultEditToolbar.vue`，结果面板内、状态条下方一行，高 32px）：

| 状态 | 左侧 | 右侧按钮 |
|---|---|---|
| 锁定 | 锁图标 + "已锁定" | `解锁编辑`（仅可编辑结果出现此工具栏；不可编辑时显示灰字原因 tooltip） |

- `保存` 仅在有改动时可用（无改动时禁用，防误触）
- 网格样式：脏单元格浅黄底；待删除行淡红底 + 删除线；新增行左侧 3px 蓝色标记条；主键列表头带锁图标且不可编辑

**保存确认弹窗**（`SaveChangesDialog.vue`，BaseDialog 420px）：

- 顶部三色摘要标签：`INSERT n` / `UPDATE n` / `DELETE n`
- 中部可折叠"查看语句"（等宽字体逐条列出将执行的 SQL 预览）
- 底部 `取消` / `确认保存`（危险色）

## 3. 接口依赖

1. **查询响应扩展**（spec-03 `StatementResult` 新增字段）：

```json
"editable": { "schema": "db1", "table": "users", "primaryKey": ["id"] }
```

`editable` 为 `null` 表示该结果不可编辑（前端隐藏编辑入口）。判定在后端查询时完成：所有列的 `ResultSetMetaData.getTableName(i)` 相同且非空 → 单表；主键列走 `information_schema.COLUMNS`（`COLUMN_KEY='PRI'`）；**主键列必须全部出现在结果列中**，否则不可编辑。

2. **`POST /api/v1/connections/{connectionId}/mutations`**（rest-api.md 第 4 节）：

```
POST /api/v1/connections/{id}/mutations
X-Joyo-Token: <token>

{ "database": "db1", "table": "users", "primaryKey": ["id"],
  "operations": [
    { "type": "update", "pk": { "id": "7" }, "values": { "name": "Bob" } },
    { "type": "delete", "pk": { "id": "9" } },
    { "type": "insert", "values": { "name": "New", "age": "18" } }
  ] }

// 200: { "code": 0, "message": "ok", "data": { "applied": 3 } }
```

- 值一律字符串传输（铁律 7）；`values` 中值为 JSON `null` 表示 SQL NULL
- 一个请求一个事务：全部成功 commit；任一条失败 → rollback → 4102（message 为 MySQL 原始错误），已改动保留在前端
- 错误码：4101 结果不可编辑 / 4102 数据变更执行失败 / 4103 主键列不可修改

## 4. 行为细节

1. **可编辑判定**（后端 `EditableResolver`）：单表 + 含全部主键列 → 可编辑；JOIN / 子查询 / 表达式列（`getTableName` 返回空）/ 无主键表 / 缺主键列 / 结果被截断 → `editable = null`。
2. **主键列只读**：改主键等于删除 + 新增，避免 UPDATE 定位歧义；前端不 enter 编辑态，后端收到主键变更 → 4103。
3. **语句在后端生成**，一律 `PreparedStatement` 参数绑定（禁字符串拼接值），标识符经 `SqlIdentifiers.quote` 反引号转义；列名按 `information_schema` 白名单校验，非法列名 → 1001。
4. **UPDATE 按主键定位**：`UPDATE \`db\`.\`t\` SET \`c\`=? WHERE \`pk\`=?`（不做原值比对，避免 NULL 比较歧义）。
5. **NULL 语义**：网格 NULL 显示为 `NULL`（沿用 spec-04 样式）；编辑态输入**全大写关键字 `NULL`** 视为 SQL NULL，其余一律字符串（小写 `null`、空串均为字面值）。
6. **本地脏标记**：改动只存前端（按结果页签 + 全局行号索引），翻页 / 切换结果页签不清空；`放弃` 一键还原。
7. **保存后刷新**：成功后重跑当前 SQL 页签的语句刷新结果（保证看到库里真实值），toast 提示影响条数。
8. **BLOB 等二进制列不可编辑**（沿用 `(BLOB)` 展示）。

## 5. 边界情况

| 场景 | 期望表现 |
|---|---|
| JOIN / 子查询 / 无主键表 | `editable = null`，工具栏显示"该结果不可编辑（需单表且包含主键列）" |
| SELECT 未包含主键列 | 不可编辑（提示需包含主键列） |
| 结果被 maxRows 截断 | 不可编辑（避免基于不完整结果改数） |
| 主键列被改 | 单元格不可进入编辑态；后端兜底 4103 |
| 保存时某条违反约束（唯一键冲突等） | 整体回滚，toast 展示 MySQL 原始错误，前端改动保留 |
| 保存时行已被他人删除 | UPDATE/DELETE 影响 0 行 → 视为失败回滚，提示"未匹配到数据行" |
| 未保存改动时切换结果页签 / 翻页 | 改动保留（按全局行号索引） |
| 未保存改动时重跑 SQL | 结果刷新后改动清空（重跑视为放弃） |
| 空表新增行 | 主键自增列留空由 MySQL 生成 |
| 后端不可达 | 常规 `BackendUnavailableError`，改动保留 |

## 6. 验收标准

- [ ] 单表有主键查询：工具栏出现"解锁编辑"，解锁后双击单元格可改，脏单元格浅黄底
- [ ] 改 2 个单元格 → 保存弹窗显示 `UPDATE 2` 并可展开查看语句 → 确认后库内值已变更，结果自动刷新
- [ ] 新增行 → 填写值 → 保存后表中确实多一行（自增主键由 MySQL 生成）
- [ ] 删除行 → 行置灰删除线 → 保存后该行从库中删除
- [ ] 一次保存含增 + 改 + 删：事务生效（构造一条会失败的操作，全部回滚且库内无变化）
- [ ] JOIN 查询 / 无主键表：不出现编辑入口，提示不可编辑原因
- [ ] 主键列不可编辑；BLOB 列不可编辑
- [ ] 保存失败（如唯一键冲突）toast 展示 MySQL 原始错误，改动仍在网格里
- [ ] 翻页后改动保留；点"放弃"全部还原
