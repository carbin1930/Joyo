- 规格编号：spec-21
- 功能名称：启动画面与后端重启（运行时可靠性）
- 所属版本：v1.0 打磨（PRD 非功能要求 + ADR-001 缓解措施）
- 状态：已定稿并实现（2026-10-27。实现说明：启动画面为 `desktop/src/main/splash.ts`（内联 HTML 小窗，主窗 ready-to-show 后关闭，启动失败也在 catch 里关闭防残留）；后端重启为 IPC `backend:restart`（stop 旧进程 → `resolveBackend` 重新拉起 → 返回新 baseUrl/token），前端在后端异常状态卡上提供"重启后端"按钮，并调用 `resetApiConfig()` 重置渲染层缓存的连接配置）
- 依赖 spec：spec-01（连接与会话）、ADR-001（技术栈代价缓解）

## 1. 功能描述

两件事：
1. **启动画面**：后端 JVM 冷启动通常要几秒，期间用户看不到任何东西（主窗 `show: false`），用一个小窗口显示"正在启动后端…"与进度条——对应 ADR-001 对"JVM 冷启动慢"的缓解措施
2. **后端重启**：后端进程异常退出后，界面除"重试"外还能直接**重启后端进程**（PRD 非功能要求："后端异常退出时给出明确提示并可重启后端"）

## 2. 界面设计

- 启动画面：360×200 无边框居中窗口，Joyo logo + "正在启动后端服务…" + 循环进度条；主窗可见后立即关闭
- 后端异常状态卡（首页）：状态点 + "后端服务异常" + 错误详情 + 两个按钮 `重试`（重查健康）/ `重启后端`（重启进程，按钮进入"重启中…"禁用态）

## 3. 接口依赖

不经过后端，走 Electron IPC：

```ts
window.joyo.restartBackend(): Promise<{ baseUrl: string; token: string }>
```

## 4. 行为细节

1. 启动画面在 `app.whenReady()` 一开始创建（先于 `resolveBackend`），主窗 `ready-to-show` 时关闭；启动异常路径也必须关闭，避免残留小窗
2. 重启流程：Main 先 `backend.stop()`（失败只告警，继续），再 `resolveBackend(isPackaged, logFile)` 重新拉起，返回新端口与 token
3. 渲染层拿到新配置后调用 `resetApiConfig()` 清空 HTTP 层缓存的 baseUrl/token，再重新健康检查
4. 开发直连模式（`JOYO_DEV_BACKEND_URL`）下 `stop` 为空操作，重启等价于重连

## 5. 边界情况

| 场景 | 期望表现 |
|---|---|
| 启动失败（jar 缺失/端口占用） | 关闭启动画面 + 错误对话框 |
| 重启时旧进程已死 | `stop` 异常被吞掉并记日志，继续拉起 |
| 重启失败（jar 被删） | 状态卡显示错误信息，按钮恢复可用 |
| 开发直连模式点重启 | 等价于重新健康检查，不杀外部后端 |

## 6. 验收标准

- [ ] 启动应用瞬间出现启动画面，主窗出现后自动消失
- [ ] 手动结束 java 进程后，首页显示"后端服务异常"，点"重启后端"能恢复
- [ ] 重启成功后版本号重新显示，查询功能可用
- [ ] 启动失败时不会残留启动画面窗口
